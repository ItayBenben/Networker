# Networker

An iPhone app that records **every network destination your phone talks to**, how often,
and how much data flows each way over time.

It works by installing an on-device VPN (a *Packet Tunnel* Network Extension). While
capture is on, every IP packet the iPhone sends passes through the extension, which notes
the destination, size, direction and time, then relays the traffic to its real destination
using a small user-space TCP/UDP stack. Nothing is sent anywhere except your own traffic.

| Tab | What it shows |
| --- | --- |
| **Overview** | Start/Stop capture, live throughput (last 2 min), bytes and new connections per minute for the last 1 h / 6 h / 24 h, totals |
| **Destinations** | Every host (or endpoint) contacted, with hostname, address, ports, bytes in/out, connection count, last seen. Search, sort, group by host or endpoint. Tap for a detail page: throughput over time, connection frequency, volume, interface, recent sources |
| **Sources** | This iPhone's tunnel addresses, current network (Wi-Fi/Cellular), traffic per interface, and the most recent local address:port pairs that opened connections |
| **Settings** | Reverse-DNS toggle, JSON export, clear data, remove VPN configuration, explanations |

## Requirements

- A Mac with **Xcode 15 or newer**.
- An **iPhone running iOS 17 or newer**. Network extensions do not run in the Simulator.
- A **paid Apple Developer Program membership**. The Network Extensions capability is not
  available to free "Personal Team" accounts.

## Build and run

1. Pick a bundle identifier of your own and set your Team ID (10 characters, shown under
   *Membership details* at <https://developer.apple.com/account>):

   ```sh
   python3 Scripts/configure.py --bundle-id com.yourname.networker --team ABCDE12345
   ```

   This writes `Config/Networker.xcconfig` and both `.entitlements` files. The app gets
   `com.yourname.networker`, the extension `com.yourname.networker.tunnel`, and the shared
   App Group `group.com.yourname.networker`.

2. Open `Networker.xcodeproj` in Xcode.

3. Xcode registers the App IDs, the App Group and the Network Extensions capability with
   your account automatically (automatic signing). If the *Signing & Capabilities* tab of
   either target shows a red error about the App Group, click **+ Capability › App Groups**
   once and tick `group.com.yourname.networker`; that forces the registration.

4. Select the **Networker** scheme and your iPhone, then Run.

5. On first use tap **Start**. iOS asks *"Networker Would Like to Add VPN Configurations"*;
   tap **Allow** (and enter your passcode). Capture starts and a VPN icon appears in the
   status bar. The app keeps collecting while it is in the background; stop from the app
   or from Settings › VPN.

## How the data is collected

- The extension claims the default IPv4 route (and the IPv6 route when the network offers
  IPv6), so all traffic reaches it as raw IP packets.
- TCP connections are terminated by a small user-space TCP implementation
  (`NetworkerTunnel/TCPConnection.swift`) and re-originated to the real server with
  `NWConnection`; UDP datagrams are relayed the same way. Connections opened by the
  extension bypass the tunnel, so there is no loop.
- DNS answers passing through the tunnel label addresses with hostnames. Addresses whose
  lookups happened before capture started can optionally be reverse-resolved by the app.
- Statistics are kept at 1-minute resolution per destination for 24 hours and written as
  JSON to the App Group container every few seconds; the app reads that file.

## Limitations

- **No per-app attribution.** iOS does not tell a packet tunnel which app sent a packet, so
  "sources" are local addresses and ports on this iPhone, not app names. (The only API that
  provides app identity, `NEFilterDataProvider`, is restricted to supervised devices.)
- Only TCP and UDP are relayed. ICMP (ping) does not work while capturing.
- While capturing, DNS goes to public resolvers (`1.1.1.1`, `8.8.8.8`, …) because a tunnel
  must name its resolvers explicitly. iCloud Private Relay and other VPNs are suspended.
- The app's own traffic (for example reverse-DNS lookups) is captured like everything else.

## Project layout

```
Networker/          SwiftUI app (views, VPN manager, snapshot reader)
NetworkerTunnel/    Packet tunnel extension (packet parsing, TCP/UDP relay, statistics)
Shared/             Models and identifiers compiled into both targets
Config/             Networker.xcconfig (bundle id base, team)
Scripts/            configure.py, generate_xcodeproj.py, make_icon.py
```

`Networker.xcodeproj` is generated by `Scripts/generate_xcodeproj.py`; re-run it after
adding or removing source files (or add files through Xcode as usual).
